# 持久记忆核对与修订建议

2026-10-15 只读核对了 Claude Code 本项目记忆中的 6 个文件。它们与 Obsidian 维护笔记不是同一套材料。本页给出可直接审阅的修订内容；本次未改动这些外部文件，也未改全局记忆。不能证明某次模型错误一定由这些文件引起，只能确认它们包含会误导后续工作的旧事实或过宽约束。

## 1. 当前定位落后于产品演进

来源 M02：[project_positioning.md](C:/Users/yicha/.claude/projects/D--8-Project-0-0----silly-tavern-explorer-main/memory/project_positioning.md)。

仍写着“AI 工具箱和书架是辅助功能（‘添头’），不要过度投入”，并将导入/导出、世界书编辑列为两大核心。这个描述适合较早阶段，已经覆盖不了 7 月归档库、9 月对话与 10 月回顾视图。

建议保留早期定位作为历史段落，把当前摘要换成：

> 截至 2026-10-15，ST Explorer 已发展为用户拥有本地资料的浏览、归档、处理与游玩工作台。早期目标是让 ST 聊天记录便于保存和重读，后续加入角色/故事资料管理、总结日记、连续回顾，以及 Tavern 对话和 Agent 文件记忆。评估功能时以用户当前的真实整理或游玩场景为依据。具体优先级、未提交工作和交付状态先核对仓库 `docs/maintenance/CURRENT.md`，再检查实际代码；不要以早期“AI 和书架只是添头”限制当前需求。

依据：[C03](evidence-index.md#c03)、[C19](evidence-index.md#c19)、[C22](evidence-index.md#c22)。

## 2. 曾经否决的功能不能变成永久黑名单

来源 M04：[feedback_feature_scope.md](C:/Users/yicha/.claude/projects/D--8-Project-0-0----silly-tavern-explorer-main/memory/feedback_feature_scope.md)。

它仍列出 swipes 浏览、与 ST 衔接等“基本用不到”的例子，并建议正则先做预设保存而非 JSON 导入导出。与现有导入、候选回复和正则兼容能力已不在同一阶段。

建议保留“不要脱离用户实际使用”这个原则，把功能名单替换为：

> 当时拒绝过的具体功能仅代表当时场景和优先级，不是永久禁令。提出或接到功能需求时，先确认它解决当前哪个操作阻碍，并检查是否已有实现。不要根据旧列表拒绝新需求，也不要重复建设已存在能力。

依据：[R02](evidence-index.md#r02)、[R04](evidence-index.md#r04)、[C31](evidence-index.md#c31)。

## 3. “重温故事”应当保留，全面禁止自动化应当收窄

来源 M03：[archive-is-reliving.md](C:/Users/yicha/.claude/projects/D--8-Project-0-0----silly-tavern-explorer-main/memory/archive-is-reliving.md)。

其理由仍很有价值，但结尾“不再提自动串联/流水线/进度清单类方案”过宽。原始笔记当时已经提出需要人工审查这条措辞，并未找到能证明用户批准永久禁令的完整回答。

建议将执行指引改为：

> 归档和重读本身可以是体验，不要默认把它们视为应被省掉的步骤。各工具应能独立使用，也能共享资料。讨论自动化时，说明它节省了哪段重复劳动、是否仍让用户控制阅读与整理过程，再按当前需求判断。

依据：[N08](evidence-index.md#n08)。这保留了原始理由，同时允许用户后来要求批量整理或后台生成。

## 6. 记忆索引自身有乱码

来源 M01：[MEMORY.md](C:/Users/yicha/.claude/projects/D--8-Project-0-0----silly-tavern-explorer-main/memory/MEMORY.md)。

UTF-8 读取时前半部分中文已经呈现乱码，同目录上述记忆正文仍能正常读取；后半索引也有正常中文。因此不能将它简单当作这次终端输出编码问题。乱码具体何时产生，本次没有追查。

建议后续先备份，再从仍可读取的文件名与 YAML `name/description` 重建简短索引；不要猜测乱码的原句，更不要从过期说明恢复一份“当前事实”。索引顶部只放当前状态入口与少量仍有效规则，历史批次可分组列出。
