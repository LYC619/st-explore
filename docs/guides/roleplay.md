# 在 STE 中开始游玩

游玩页使用 TauriTavern 保留的 SillyTavern 1.18.0 原始界面。顶部抽屉、角色面板、消息编辑、候选切换、预设与世界书编辑都沿用酒馆的操作。STE 负责保存角色、故事、分支和连接配置。

[查看本轮实际界面截图](../verification/ste-roleplay-runtime-classic.png)。

## 第一次打开

1. 在 STE 设置页配置一个 Chat Completion 连接，填写完整接口地址和模型名。本地接口可以不填密钥。网页运行时，接口需要允许浏览器跨域请求。
2. 在资料库导入角色卡，进入角色详情，点击 **新开聊天**。酒馆会读取原卡的开场白，创建一条 STE 故事。
3. 已有聊天记录可以从 STE 导入，打开故事后点击 **开始游玩**。在故事中选择分支后进入，会继续该分支。
4. 在酒馆 API 抽屉选择 **STE 主模型**。输入一句话并发送即可；回复与编辑会自动保存。

游玩页左上角的 **返回故事** 会先保存当前编辑，再返回 STE 的阅读和整理界面。原版角色导入、角色卡导出、聊天导入等按钮会打开对应的 STE 管理页。

## 两种模式如何选择

在原版 **扩展** 抽屉展开 **STE 游玩与记忆**：

| 选择 | 发送后发生什么 | 适合的连接 |
| --- | --- | --- |
| 无 Agent · 原酒馆流程 | 按原酒馆预设、关键词世界书和正则生成回复 | 普通文本模型即可 |
| Agent · 自动查阅资料与记忆 | 工具 Agent 查资料，主模型写正文，保存回复后工具 Agent 更新记忆 | 主模型不必会工具调用；工具模型必须支持工具调用 |

两个模式使用同一份故事，可以在没有生成任务运行时切换。工具模型在 API 抽屉单独选择；未单独选择时使用主模型连接。

Agent 模式里，主模型仍接收上下文窗口内的长历史。工具 Agent 只先看到有限的近期内容和资料目录，按需要搜索并读取世界书、笔记和历史原文。它会给出文风、视角、角色知情范围与未兑现约定的提醒，正文仍由主模型续写。

每轮送给主模型的补充资料会固定下来。后续新增资料随新回合追加，减少反复改写旧前缀。编辑旧剧情、切模型、改变预设等情况可能开启新的上下文周期；面板会显示原因。**前缀可复用不等于服务商一定命中缓存**，实际命中率要看所用接口的统计。

## 世界书与记忆

无 Agent 模式沿用酒馆的世界书扫描和深度注入。Agent 模式把蓝灯条目放在稳定的前文区域，由工具 Agent 选择本轮需要的绿灯资料；人物或地点切换不需要用户手动开启条目。

世界书的长期变化先生成 **版本草稿**。在 **世界书版本** 中查看原文、修改原因和来源，接受后作用于当前分支；原资产保留。修改来源剧情会使相关版本失效。

在 **查看 / 修改记忆** 中能看到实际 Markdown 文件，例如：

| 文件 | 内容示例 |
| --- | --- |
| `state.md` | 当前时间、地点、在场人物与即时状态 |
| `characters/林.md` | 身份、关系、角色知道与不知道的事情 |
| `events/北门.md` | 已经发生的事件与证据 |
| `threads/铜钥匙.md` | 约定、伏笔，以及解决或取消状态 |
| `style.md` | 文风、视角约定和可以参考的原文片段 |

工具 Agent 只在回复成功、被采用且正文保存完成后自动维护事实记忆。停止的半段回复可以保留为正文，但不会当作一次成功生成自动归档。编辑、删除或切换候选后，旧来源会被重新校验。

手动保存的笔记由用户维护，Agent 会读取并保留它。若外部编辑与自动写入冲突，界面会提示冲突，保留现有文件。记忆维护失败不会撤销已经保存的正文；在扩展抽屉点击 **补全记忆** 可重试。

桌面文件库在对应故事目录下保存 `memory/main/` 与 `memory/branch-…/`。浏览器和 Android 使用本地存储保存同样的逻辑文件，并可通过完整故事包迁移；不会假装浏览器已直接访问系统文件夹。

## 分支与候选

候选切换、编辑和停止仍使用原版消息按钮。原版 `/branch-create 0` 表示从第 0 楼创建分支；在其他位置分叉可使用相应楼层编号。

新分支继承截至分叉位置仍有依据的记忆、已接受的世界书版本，以及父分支的游玩模式。后来才发生的事实不带入早期分支。生成任务和缓存记录重新开始；父线正文与笔记不会跟着子线改写。导入的旧分支若没有明确的父线记录，不会根据名称猜测继承关系。

## 使用柏宝书

当前适配 **ST-BaiBai-Book 1.2.7** 的指定源码版本：
[`5c8a6b60d8c1185e169c46d43f63fce7d35d8583`](https://github.com/baibai-git/ST-BaiBai-Book/tree/5c8a6b60d8c1185e169c46d43f63fce7d35d8583)。从该提交获取原版源码 ZIP，在 **STE 游玩与记忆** 里的 **柏宝书原版插件** 安装。插件代码由用户提供，STE 不随程序分发该代码。

选择 **无 Agent**，再把 **记忆维护** 设为 **柏宝书**。摘要调用 STE 的工具模型；可以在柏宝书原面板查看摘要、物品、NPC、场景和悬念。STE 文件记忆与柏宝书不会同时自动维护同一分支。

已验证自动摘要、滑动窗口隐藏、注入、台账、重开聊天以及候选摘要归属。这个版本在手动修改正文后仍保留原摘要；如果剧情含义改变，需要在柏宝书里手动重摘。切回 STE Agent 时，会撤销由柏宝书接管的隐藏，保留其接管前已经手动隐藏的楼层。向量功能、旧 Horae 迁移和全部高级配置尚未验收，完整范围见[兼容说明](../principles/extension-compatibility.md)。

## 内置脚本与交互内容

在扩展抽屉的 **内置助手 · 脚本与交互内容** 中导入常用酒馆助手脚本 JSON。导入后先选择需要的读取、修改或工具模型能力，再启用。脚本按钮会显示在同一面板；HTML 交互代码块需要单独开启。

首版支持消息读取、部分消息修改、聊天/楼层/全局/脚本变量、事件、脚本按钮、常用宏和斜杠命令，以及非流式辅助生成。异步更新若遇到另一处修改，会提示重新读取，避免覆盖新状态。页面提供 **支持范围**，列明实际接口。

这不是完整酒馆助手宿主。依赖任意外部模块、直接操作父页面或未适配 API 的脚本需要调整。内嵌 HTML 只在附近可见区域运行，切换聊天会卸载。

## 备份、迁移与恢复

- **酒馆聊天列表的 JSONL 导出**：保存该聊天的正文、候选和扩展字段，适合 ST 互操作；不包含独立记忆文件。
- **完整故事包 `.ste-play`**：在游玩扩展抽屉或故事导入导出页导出。包含全部分支、角色、引用的预设/世界书/正则、文件记忆及必要运行记录。在资料库或故事页导入时先预览；同 ID 不同内容会阻止导入，不会默默覆盖。
- **完整 Web 备份**：保留本地资料及游玩配置。已知连接凭据字段会被剔除；恢复后仍应检查模型连接。

故事包不携带连接密钥、已安装插件/助手脚本配置和本机外部附件。导入预览会列出省略内容。聊天与楼层中的变量保留；需要执行的脚本在新环境中另行安装和启用。

关闭或刷新时，尚未提交的输入和消息编辑会留一份草稿。重新打开时可以选择恢复或丢弃；源故事已变化时会提示冲突。正文保存失败会阻止正常退出，并保留界面供重试。

## 当前适用范围

本地 Chromium 浏览器已完成自动化游玩验证，Windows 程序已构建；Windows WebView2 实际窗口与 Android 真机尚未验收。测试使用本地模型夹具，没有消耗用户接口额度。实际剧情质量、长时间游玩体验和远端缓存命中率仍需要用自己的模型试玩。

本轮接入的是单角色游玩与故事分支。群聊、自定义背景/用户头像上传、TTS、插图、完整扩展市场以及任意后端插件不在已验收范围。

开发者运行方式与测试证据见[实现与验证记录](../verification/ste-roleplay-runtime-v1.md)。
