## 实际接缝与交接约定

- 新增 `MemoryPanel` / `MemoryCaptureSheet`，保留原 ST 正文树。面板每次呈现 40 张卡片，更多按需展开；Switch、抽屉关闭与按钮热区至少 44px，原文字体与主题沿用。
- 楼层保存默认标题＋原文摘录，不调用摘要模型；高级设置提供重要程度和固定设定。固定设定仍保留来源；默认摘录在来源编辑／候选变化后待核对。删除采用 tombstone，恢复后默认停用。失败保留草稿与来源。
- 标准聊天“使用记忆”默认关闭；开启后用现有分词器在约 1200 token 内容预算内排序选取，并校验最终请求上下文。Agent 的检索及维护排除停用／删除项；手动正文防覆盖；柏宝书仍互斥。请求准备时记忆变化会拒绝旧快照，旧 ledger 周期不会沿用已撤销资料。
- `TurnReceipt` 的锚点包括 story/branch key、选中 epoch、SourceRef、正文／变量摘要和 operationId。由已保存故事读取，ST `waitForGenerationIdle`、原版助手、柏宝书的已知 flush 与正式保存后形成。阅读位置等非剧情元数据不导致误失效。未知第三方扩展的任意异步写入尚不能宣称完整结算，后续自动推演不得直接据此放行。
- 本批解析 `<choices>…</choices>`、`[choices]…[/choices]` 或 choices 代码围栏内连续编号的 2～4 条，文字≤240字符；拒绝 HTML、控制字符、宏及重复项。无明确块不显示按钮，也不补模型调用。原文不删除；并非自动生成推荐行动。
- 点击立即锁定卡组，重读保存状态；草稿非空则只追加。ST `sendMessageAsUser` 原输入正则仍生效，随后 `Generate(normal, automatic_trigger)`；不经过 slash 解析，额外元数据在玩家楼层首次保存前写入。operationId 同正式正文一起落盘；保存拒绝重复 operationId。失败不自动重放，玩家楼层已存在时沿原 ST 继续。
- `play-completions` 是宿主观察到的模型结束状态，`play-receipts` 是已保存正文／变量的派生凭据；ProcessLog 仍只负责解释。历史导入的完整楼层可解析选项；本应用生成但缺少成功完成记录时保守不显示。
- 分享 `.ste-play` 对采用新记忆控制的故事省略停用／删除记忆、记忆索引及全部可能含旧正文的 roleplay 控制历史（含旧分支继承计划）。保留允许分享的当前记忆；这意味着该包不再包含原 Agent 周期和运行设置。UI 列出省略说明。文件库完整备份保持原机制；已有故事正文内的同一事实不会被删掉，不把停用记忆误称作从故事中抹除信息。
- Batch 1 顶栏只显示“标准”胶囊。分支、脚本、聊天工具、玩法、帮助、关闭移入“更多”，原入口目标保留。完整多模式 Segmented Pill 及 GAL 立绘、RPG HUD、Observer 胶囊在各自批次验收。
