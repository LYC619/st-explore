# STE 角色扮演运行时实施记录

日期：2026-09-12。用户已授权自主实施。功能位于隔离分支 `codex/ste-roleplay-runtime`，原工作区的用户修改保留；未合并、推送或发布。本文件按实际实现更新，验证结果以[实现与验证记录](../../verification/ste-roleplay-runtime-v1.md)为准。

目标是让用户在熟悉的 SillyTavern 界面里打开 STE 的角色与故事，选择无 Agent 或 Agent 模式，发送消息后自动完成所选流程。主模型承担长历史与正文，工具 Agent 按需读取资料并在回复保存后维护 Markdown 记忆。插件范围为内置常用助手能力，优先适配柏宝书的非向量功能。

设计依据：[总体设计](../specs/2026-09-12-ste-roleplay-runtime-design.md)。用户操作见[使用说明](../../guides/roleplay.md)，具体插件边界见[兼容说明](../../principles/extension-compatibility.md)。早期 P0 草案与已作废的自绘聊天界面计划不作为执行入口。

## P0：固定真实上游和接入契约

已实现：

- 固定 TauriTavern `9693a4ec47cd4552f90878bccab453f176de0f18`，2.2.0 / ST 1.18.0；保存 1,137 个原文件、来源清单、逐文件 SHA-256、原始许可与依赖锁。
- 原始应用模块保持原 URL 和模块关系；根构建生成六个 Rspack 依赖/设置输出。STE 覆盖层在校验原文件后单独生成，开发和生产使用同一资源映射。
- STE 父页面持有仓库、连接与凭据。同源原版 iframe 持有运行中的 `chat[]`；持久化正文只有 `ArchiveStory`。
- 固定聊天、候选、设置、资产、生成与保存的实际契约。原入口、抽屉和消息操作保留。

主要文件：`vendor/tauritavern/`、`scripts/tavern/{source,build,runtime-build,host-overlay,vite-plugin}.mjs`。执行包：[上游接入](2026-09-12-ste-tavern-source.md)。

## P1：原始界面、故事与生成生命周期

已实现：

- 角色页“新开聊天”，故事页“开始游玩”，以及返回故事、选卡、聊天列表、重命名、搜索和分支导航。
- 首次新聊天由原版流程展开开场白；一次性初始化标记随首次保存消费，重开不会重复插入。
- 角色、主线、分支、消息和候选采用稳定身份。隐藏消息、空消息、未知插件字段与所有候选继续保留。
- 发送、流式回复、停止、消息编辑、候选切换和保存接入同一故事更新队列。持久化确认等待 IDB 事务完成，文件库写入使用已有原子文件能力。
- 模型沿用 STE 连接 ID 和完整接口地址，支持 YAML 请求映射、SSE、取消、usage 和错误。只接入 Chat Completion 传输。
- 导航、聊天切换和关闭先完成保存；失败保留界面并允许重试。文件库 epoch 防止迟到任务写到新库。
- 输入框和未结束的消息编辑有稀疏草稿检查点，刷新后可恢复。

主要文件：`src/pages/Roleplay.tsx`、`src/lib/roleplay/{frame,catalog,live-chat,story-session,start-story,tavern-host,provider,draft,completion-monitor}.ts`、`src/tavern/{host-bootstrap,draft-recovery}.js`。执行包：[原版宿主](2026-09-12-ste-tavern-host.md)。

## P2：无 Agent 模式与现有资产

已实现：

- 使用原版 ST 的预设与消息组装、世界书扫描/深度注入、宏和 JavaScript 正则执行器。
- 读取 STE 角色、PNG 元数据、预设、世界书和正则。角色/世界书编辑保留未知字段并检测陈旧版本；PNG 编辑同步到原卡数据。
- 故事关联世界书参与有效条目集合。关联正则保留原数值 placement；WORLD_INFO 为 5，不使用 STE 旧显示标签猜测转换数据。
- 角色/聊天/世界书导入及角色导出按钮打开对应 STE 管理页。原聊天列表支持 JSONL 和纯文本导出。
- 未接入的群聊、自定义背景/用户头像上传有明确提示。未提供的后端路由返回错误。

主要文件：`src/lib/roleplay/{assets,regex-assets}.ts`、`src/tavern/regex-assets.js`、`src/lib/st-regex-interop.ts`。

实际浏览器用例检查关联预设、故事世界书、宏与原版正则编辑后的最终模型请求。该结果证明所测样本；不能据此声称每一种 ST 配置排列均已验收。

## P3：自动工具 Agent、文件记忆与分支版本

已实现：

- 一次发送进入有界工具循环：最多 6 轮模型决策、12 次工具调用，初始仅有限近期内容和资料目录，可继续搜索/读取世界书、记忆与历史原文。
- Agent 模式蓝灯资料进入稳定前文；动态资料和提醒按回合冻结。主模型使用窗口内原历史；最终 Provider 请求经过 YAML 映射后才进入前缀检查。
- 记录本地相同前缀估算与服务端报告的缓存量，不把本地相同前缀计作服务端命中。
- 原生事实记忆只在生成成功、采用回复且正文持久化完成后自动维护。Markdown 文档带消息、候选、内容摘要等来源；编辑/候选变化后失效。
- 小型准备/提交日志支持部分文件写入后的幂等恢复；手动笔记和外部修改冲突会保留。维护失败可独立重试，不撤销正文。
- 世界书更新生成版本草稿；用户接受后只在对应分支生效，原资产保留，来源变化会失效。
- 新分支按分叉来源继承有效记忆、手动笔记、接受的版本和模式。较早分叉可从已提交历史恢复适用记忆；不继承生成任务、缓存轨迹或可执行脚本配置。

主要文件：`src/lib/roleplay/{agent-runtime,tool-agent,context-ledger,fingerprint,memory,runtime-store,worldbook-versions,branch-inheritance}.ts`。执行包：[Agent 与记忆](2026-09-12-ste-roleplay-agent.md)。

当前默认工具工作上下文约 8k token，补充资料约 2.2k token。预算是约束和调优起点，不能保证具体模型的剧情质量。

## P4：内置常用助手与柏宝书

已实现：

- 内置脚本 JSON 导入、显式启用与能力选择、脚本按钮、聊天/楼层/全局/脚本变量、消息读取与受限修改、事件、常用宏/斜杠命令，以及非流式工具模型生成。
- 脚本和 HTML 使用独立来源 iframe，通过快照与 RPC 访问获准资料。挂载数量受限；切换聊天清理脚本、监听和待处理请求。
- 变量保存使用基线冲突检查。失败的 script.data 写入恢复已保存快照；异步 updater 不覆盖其等待期间产生的新值或新候选。
- 用户提供的柏宝书 1.2.7 指定 ZIP 经过哈希校验，链接到真实 ST 模块。摘要走工具连接；测试使用实际插件，验证自动摘要、隐藏窗口、注入、台账、候选归属和重开。
- 分支只允许一位自动记忆维护者：无、柏宝书或 STE Agent。归属切换时恢复柏宝书接管的隐藏，保留接管前的手动隐藏。

执行包：[助手与迁移](2026-09-12-ste-helper-and-portability.md)。支持 API 和未验收功能以兼容说明为准。完整酒馆助手、任意前端插件和全部柏宝书高级功能不属于本次兼容承诺。

## P5：恢复、迁移与验证

已实现：

- `.ste-play` 包含故事全部分支、角色和关联资产、记忆与必要运行记录；导入先预览，遇到同 ID 不同内容拒绝覆盖。
- Web 以单次 IDB 事务导入；桌面文件库先暂存、验证，再发布。备份覆盖游玩侧文件和经过凭据过滤的设置。
- 可分享故事包省略连接凭据、可执行插件/助手配置与本机外部附件；普通 ST JSONL 导出保持其互操作职责。
- 浏览器测试覆盖实际原版 iframe、保存/恢复、请求内容、分支与插件。2,000 楼样本检查 DOM 数、工具输入大小、流式写入次数和本地耗时；50 次重载检查监听器及 iframe 生命周期。

最终检查包括完整 Vitest、TypeScript、ESLint、固定上游来源检查、完整 Playwright、生产构建和 Rust 本地检查。命令、结果、性能测量和尚未通过的项统一记录在验证文档，避免用过时的阶段计数判断完成。

- Windows WebView2 和 Android 真机上的打开、原生关闭/返回、文件权限、恢复以及不同尺寸的交互。
- 所用远端模型的真实工具调用、首字延迟、成本与服务端缓存命中率。
- 同一长剧情的事实遗漏、角色知情范围、文风稳定与伏笔连续性，以及 ST 老用户的实际操作体验。
