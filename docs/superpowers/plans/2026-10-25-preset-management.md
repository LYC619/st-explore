## 目标与建议范围

把预设从“按标题找一个 JSON，再打开编辑”提升为可按模型、用途和自己的使用经验筛选的资料库。建议第一批交付模型标记、管理表格、详情、批量整理及所有 STE 选择入口的一致展示；第二批补版本对比、试用记录与配套资料；第三批再做 Obsidian 笔记导入及按实际运行模型辅助选择。

不重做提示词编辑器，不扩大到世界书／正则全局改版，不自动更改当前聊天模型或启用配套脚本。

### 模型标记规则

“标注适配”和“实测结果”分别保存。一个预设可有多个模型目标，每个目标支持家族或具体型号、信息依据、必要条件；依据可为作者说明、个人填写、识别候选。只有个人明确记录的测试才显示“有试用记录”，自动识别不生成“已验证”。

1. 手工标记是确定值。`claude`、`Claude` 等别名统一展示，具体模型名称允许自定义，避免写死模型版本列表。
2. 文件名、原 JSON 模型字段和说明属性只能产生待确认候选。`3.1 D` 等首先是原文版本标签，不能自动当作模型版本。
3. “开源”放模型类别／自由标签；能确认 DeepSeek 等再补具体家族。“写卡”放用途；“通用”显示为适配声明，不表示支持所有模型。
4. 筛选默认“所选家族或型号任一命中”，不同维度相交。具体型号优先显示精确标记，家族标记显示“仅家族标注”；可以包含未标注项。
5. 选择时展示所选预设的条件，例如需关闭思考、需指定后处理方式；提示来自资料，不自动改 API 配置。
6. 第一批提供手动选模型筛选。后续“按当前模型筛选”必须读取相应生成入口实际生效的模型；总结模型与原酒馆模型不能混用。无法识别时保留全部选项。

## 页面与入口

### 附属库 → 预设：主要管理入口

保留现有唯一左侧类别导航。内容区顶部放搜索及模型、用途、状态、标签筛选，第二行提供“全部／收藏／待试用／使用中／已停用”、分组和排序。默认不显示已停用，但显示隐藏计数和清除筛选入口；已有引用照常可用。

桌面默认表格，保留紧凑卡片切换。建议默认列：名称及版本、适配模型、用途、状态、收藏、备注摘要；作者、代表卡片、来源和时间可选列。按模型或系列分组时，同一预设在多模型分组可出现多次，批量选中仍按唯一 ID 计数。

点行选中并在右侧看详情，不立即离开列表；明确的“编辑预设”按钮进入原编辑器，保留原 `assetId`、角色上下文和返回目标。进入编辑再返回，恢复搜索、筛选、排序、滚动和当前项。双击可以快捷编辑，键盘有同等入口。

右侧详情包含“管理资料／自用记录／引用与来源”；第二批增加“试用记录／版本与配套”。修改表单明确保存，关闭或切换有未保存提示；收藏等轻操作即时保存，失败恢复旧状态并提示。

窄屏使用卡片、筛选抽屉和全屏详情，不将桌面多列表格强行压缩。

### 编辑区 → 预设：快速选择入口

保留 `/tools?focus=preset` 的“选好再进编辑器”关系，复用管理目录的摘要、搜索和筛选组件，以选择模式展示。预设编辑器增加“管理资料”入口，正文与标记共同保留未保存保护；从角色进入时保留该角色的引用与派生规则。

### 角色挂载、总结与其他选择器

统一显示“名称／版本 + 模型标签 + 收藏或使用状态”，支持标题、作者、标签搜索；显示已选中但已停用的条目，允许继续使用或明确更换。更换候选不自动改角色引用；只有用户执行现有确认操作才保存引用。

原酒馆内嵌界面有独立预设选择器，不能仅靠 React 组件改动承诺同步。第一批覆盖 STE 自有入口，后续确认桥接接口后再接原酒馆筛选与模型提示。

## 批量整理与导入

第一批支持多文件 JSON 导入及批量设置模型、用途、状态、系列、收藏、增删标签。每次明确“追加／移除／替换”，混合值不得在用户没操作时被清空；部分失败列出项目，成功项不重复执行。批量删除沿用现有引用预览、文件保留和确认流程。

导入先给逐文件预览：格式是否有效、同内容／同来源候选、识别模型、建议系列和版本。精确重复的比较基于规范化 ST 内容、排除 STE 管理字段和 JSON 排版；相似标题只提示。遇到同内容但不同资料标记，可保留现有或显式合并资料；不静默覆盖备注。不同内容默认另存，用户可将其归入同系列；“设为推荐版”不改变既有角色绑定。

现有独立编辑器的导入历史是最多五份自动保留。用户给自动保留项正式保存管理资料、收藏或批量标记时，第一批应将该条设为永久保留并说明，避免辛苦整理后被自动清理。批量管理导入默认永久入库，不沿用临时历史上限。

第三批再导入 `02_Presets` 笔记：解析属性、Markdown、`[[链接]]` 与 `![[附件]]`，一篇可手动映射多个预设；找不到实际 JSON 只进入待匹配说明队列，不伪造可执行预设。需要附件根目录时让用户选择，不扫描整盘；保留原文和来源路径。`99_存档` 只作来源目录，`过期` 也仅作为状态候选。旧“最后更新”按原始含义保留为笔记更新时间，不伪装成预设发布时间。

## 版本、配置和试用记录

系列分组第一批只做轻量归类，不预设所有版本都符合数字版本规范，不自动取“数字最大”为推荐。用户可分别推荐某家族的版本。

第二批每个发布版本／模型变体仍是独立 `PresetItem.id`。自改版记录来源 ID，原文件保留。差异比较按提示词 identifier 对齐，重复或不可靠 identifier 必须提示，不依靠名字直接覆盖。

每条试用记录包含日期、模型与可选渠道显示名、对应版本／内容指纹、启用组和参数摘要、角色／故事链接、表现结论、优缺点及可选评分。不保存密钥等连接秘密；关联对象删除后留文字快照。作者评价、旧笔记摘录和本人的实测分开，修改预设后标注“针对旧配置”，不继续显示为当前版本已测。

只提供手动记录与对照，不自动批量调用模型评分；不安装后台更新监视器。配套说明可以打开来源链接，手动查看更新；网站采集与同步属于另外的授权和实现范围。

| 位置 | 预期工作 |
| --- | --- |
| `src/types/preset.ts`、拟新增 `src/lib/preset-catalog.ts` | 目录类型、规范化、筛选、分组、排序和识别候选；旧数据缺字段有安全默认值 |

| `src/pages/AssetLibrary.tsx`、`src/pages/Tools.tsx` | 预设专用管理／选择模式，共用目录逻辑；保留世界书、正则和其他资产导航 |

| `src/lib/asset-cow-save.ts` | 仅对预设按明确策略传递作者、系列等描述资料；派生副本不继承个人实测为已验证；不改世界书和正则行为 |
| `src/components/summary/AttachPanel.tsx` 及其他 STE 预设选择入口 | 共用摘要展示和筛选；选中 ID 稳定、已停用项不静默失联 |
| `src/lib/vault/st-import.ts`、独立 JSON 导入及备份链路 | 保存管理资料、重复候选、来源只读、备份完整性；不自动改变现有同源重导语义 |

文件库已有 `steMeta`／`serializePresetFile`／`decodePreset` 将记录元数据写入并恢复 `__ste`；沿用该机制，IDB 沿用现有 store。实施时验证 lossless 表示、复制、备份、原生序列化均保留目录字段，不能仅因函数展开了对象就声称持久化完成。

导出 ST 兼容 JSON 时管理资料默认不进入提示词或模型请求；完整 STE 备份保留，单独分享资料档案作为后续可选导出。新增字段不得改变原预设的未知参数及扩展还原。

管理资料是当前库对该预设的整理信息，单独修改它不创建角色派生副本，也不把预设内容标成已改写；实际编辑提示词继续走既有角色派生保存。内容修改时间和目录修改时间独立。新派生项可复制作者／系列／声明信息，但收藏、个人评价和当前内容的测试结果不自动继承。

第二批试用记录和配置快照应使用独立记录／按需加载，避免无限追加到第一批目录摘要。存储格式、备份及清理策略随第二批具体设计确定，第一批不提前新增大套版本系统。
