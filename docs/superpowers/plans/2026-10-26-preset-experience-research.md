# 预设收藏体验：同类项目、真实样本与独立审查

研究日期：2026-10-26。执行：Codex 子 agent `preset_research_review`。起点 `codex/playtest-1007@18e820e`；实施由主 agent 并行进行，下面“原界面”均指用户截图和此起点，不将正在变化的代码当成最终验收结果。

本轮范围是把预设库做成方便自用的收藏与取用入口。不是把用户 Obsidian 属性逐项翻译成网页表单，也不新增社区联网下载、自动模型试用或批量迁移真实资料。

## 1. 原界面为何比手记还费劲

用户截图中，浏览一份预设前先遇到三排筛选／分组／选择控件。未整理的每条记录有一条与自身名称重复的分组标题，又重复显示“未标版本、未标模型、待整理、未引用、0 附件”。打开详情后，同时展示五个操作、统计、时间和完整编辑表单，说明正文反而在下面。这是在让用户填写数据库，尚未替用户完成“认出它 → 看说明 → 取用”的工作。

这不是单纯减小字号或按钮的问题。详情中展示重要信息和编辑资料应是两个状态；筛选应按频率分层；没有分组价值时不应输出重复分组行；已经能从文件名读到的信息不应要求用户再抄一遍。

只读检查了两个目录，共 60 份 JSON：

结构统计：提示词数量从 12 到 220；60 份都没有根级 `author` 或 `version`；46 份同时存有多个模型字段。仅保存名称、结构计数和字段存在情况到 `.local/research/2026-10-26-preset-experience/sample-metadata.json`，未复制正文到受版本管理代码、未执行脚本、未改来源。

| 真实名称模式 | 可以提出的线索 | 不能推断的内容 |
| --- | --- | --- |
| `[哈基米2.5]World_Builder_1.4.json` | Gemini；版本 1.4；展示名 World Builder | 方括号内 2.5 是模型线索，不能误作预设版本；不能猜作者 |
| `【小猫之神】3.10.json` | 版本 3.10、系列线索“小猫之神” | 名称可能是系列或作者昵称，不能直接写入作者字段；模型留空 |

| `【gemini】kemini 4o 0706超级版 (1)` | Gemini，0706 可作发布版本线索，(1) 是下载重名后缀 | “4o”可能是系列组成，不应因它再追加 GPT 适配结论 |
| `[Claude]MUR 鹿鹿 API 4月29日`（截图名称） | Claude、4月29日发布标签 | 不能补造年份，也不能当成完整发布日期 |

| `斯拉预设 Claude 4.5 test` | Claude 名称线索 | 模型后直接相邻的 4.5 可能是模型代际也可能是预设版本，保守不自动填版本 |

**重要反例：**样本中有文件名写 Claude、`openai_model` 却留着 Gemini 的记录。现有 `detectSourceModel` 会跨多个 provider 字段 fallback，适合显示“有哪项配置”，不适合用来宣称适配性。新建议优先文件名的明确模型；配置只读当前 `chat_completion_source` 对应字段，`makersuite` 映射 `google_model`，`custom` 只取 `custom_model`。未选中的模型字段是旧值，不能合并成“全适配”。

已有库的这些推断只改变展示，不写回管理资料。导入可以预填并显示“从文件名识别，可修改”；详情整理可以一键采用候选。用户确认的非空作者、系列、版本、模型、用途逐字段优先，候选不能覆盖。用户把某字段留空与“没有记录过”目前没有独立数据标记，因此展示候选仍须保持明显的推断身份。

## 4. 本轮展示建议

1. 一级“预设库”在角色库后；编辑区的预设入口仍能直达选择／编辑，但复用同一收藏体验。旧 URL 保持兼容，返回带回所选项、过滤和位置。
2. 首屏保留标题、搜索、导入，收藏／全部等常用切换可轻量显示。高级筛选和排序集中在一个弹出区域，只有生效的条件显示为可移除标签；正常浏览不出现选择圈。
3. 默认用紧凑的收藏卡或清晰列表：名称、版本与少量模型标签、最多两行说明摘要；未填字段直接省略。系列有多个版本时才提供版本切换，单条记录不生成同名分组大标题。模型用标签区分，不滥用图标猜品牌或给每条加随机封面。
4. 当前预设详情先显示作者说明／自己的笔记、可识别结构与附件；主动作是“取用”和“复制后 DIY”，管理资料点击“整理资料”后再编辑。删除、重命名等放次级操作。没有说明时，用实际文件结构和下一步操作构成空态，而不是列十几项“未填写”。
5. 模型、用途、状态可点选已有选项；自定义仍允许输入。作者与系列复用已有值，导入同系列新版带共同资料，重填仅限版本和本次说明。多文件导入逐项覆盖仍可用，但不应同时展开每个完整表单。
6. 保留资料与源文件关系：版本分组只是浏览组织，不合并内容、不移动原资产、不改角色引用；资源详情可看内嵌脚本但永不执行。

## 6. 挑剔试用标准

- 用 12—20 份真实样本组成隔离库，至少三份同系列不同版本、长名称、完全无 catalog、多个模型字段残留和 200 个提示词。只展示一个手工造得很整齐的预设不算验收。
- 1366×768、1440×900、宽屏和窄窗口：打开即能辨认至少数份预设；首屏不被筛选和表单占据；正常模式没有批量圈；详情主操作不遮盖正文；没有白色滚动轨道或横向溢出。
- 在 cocoa、ink、midnight、cream 四主题切换后检查滚动、输入、下拉浮层、模型标签和焦点。角色信息收起后不能多出“比控件还显眼”的空条或滚动条。
- 从真实文件选择导入一份未整理预设，不输入文本也应得到可识别名称、版本候选和结构信息；只改有误线索，再加入作者说明与附件。用计数记录真正必须手敲的字段，不能把“支持自动识别”藏成每条都要点的多个按钮。
- 连续走：选择 A → 看说明 → 看正则／脚本 → 切另一版本 → 回列表 → 编辑 B → 保存 → 返回 → 挂载到总结／故事树。期间筛选、标题、版本和选中 ID 不漂移。
- 退出整理时有未保存内容要可保存／放弃／取消；取用目录或 DIY 失败不能假装成功；确认原版与既有角色引用未改，附件仍随新副本保留。
- 单独列出仍不顺手的动作，不用测试通过替代用户体验评价。每个发现对应入口、操作、截图或行为证据，再决定修复或说明边界。
