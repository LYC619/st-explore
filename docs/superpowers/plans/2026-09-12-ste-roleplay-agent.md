# STE 工具 Agent 与文件记忆实施包

用户已授权自主实施。本包继续使用同一个原始 ST 页面、故事仓储和连接配置。

状态：已执行。本包保留实施步骤，最终支持范围、结果和平台限制见[实现与验证记录](../../verification/ste-roleplay-runtime-v1.md)。

1. `runtime-store.ts`：捕获库，将同一逻辑文件映射到故事目录或 Web/Android 的 `roleplayFiles`；目录/文件名不接受穿越。全文备份包含这些文件。
2. `memory.ts`：可读 Markdown + 来源引用 + 小型 prepared/committed 增量日志。写入在已有故事队列中校验当前来源及磁盘摘要；恢复不覆盖手动变更，检索排除半写入和失效记录。
3. `tool-agent.ts`：最多 6 轮/12 次工具调用，仅带当前输入、4 对近期消息、状态/目录；提供检索和原文读取工具。最终资料由宿主从已读取来源装配，主模型不收工具轨迹。
4. `context-ledger.ts`：每轮资料冻结、追加；在 `prepareCompletion` 之后检查实际发出的请求前缀。输入/预设/资产/分支变化建立新周期并记录原因，显示实际 provider usage 与本地估算的区别。
5. 生成记录绑定当前故事/分支/源历史/候选。仅成功终止且当前采用的回复获得持久保存确认后维护记忆；停止、失败、保存失败、废弃候选不写事实。下一轮等同分支写入屏障。
6. 原始扩展抽屉提供模式、记忆查看/修改、引用与世界书版本入口；原 API 抽屉选择两套既有连接配置。原世界书自动变化只产生分支版本，原件保留。

先做来源/日志/请求/取消的确定性测试，再用原始界面与本地 Provider fixture 测自动检索→正文→持久保存→记忆维护，以及编辑/候选/分支隔离。外部模型质量与服务端缓存率只记录实际测量，不从 fixture 推断。
