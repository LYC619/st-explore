# 聊天入口、上手引导与保存恢复

用户实测反馈的 Windows 保存错误与入口问题，继续在现有原版 ST 前端和 STE 数据体系内修正。

## 保存与退出

原生测试已复现新建聊天后的假冲突：首次开场白落盘后，后续保存被误认为其他编辑修改。先用文件库的并发读取/保存回归定位缓存与落盘的一致性，保留真正的正文冲突检查。原版保存提示必须显示宿主返回的具体原因，不能只抛空 statusText。

保存失败时保持聊天可见，提供重试、导出当前内容和明确确认后退出。导出要包含当前正文、候选、尚未提交的消息编辑和输入框；不能依赖已经失败的正文保存。离开前尽力保存恢复草稿，无法保存时如实说明。用户决定丢弃未保存改动后，应用必须能退出；不得把失败描述为自动保存成功。

## 独立聊天模块

侧栏与移动导航增加“聊天”，路由为 /play；既有 /chat 聊天处理工具保留。聊天页提供最近对话、搜索及选择角色新开聊天，用户不必先进入角色或故事详情。实际对话继续使用 /play/:id 的原版酒馆界面。由聊天模块进入时返回聊天列表，既有故事入口仍能返回原故事。

## 首次使用

聊天页直接说明三种玩法：无 Agent 用主模型对话；STE Agent 自动查世界书和文件记忆，需要工具模型；柏宝书在无 Agent 下提供摘要与台账，需要安装指定插件包。对话页常驻可发现的“玩法设置”和“使用帮助”入口，帮助给出连接、模式、插件安装的下一步操作并可重复打开，不要求用户记住原版抽屉图标。

## 验收

文件库保存竞争回归、真实并发编辑保护、原版错误文本、失败时导出/退出、独立入口与模式引导分别验证。最终用隔离身份的 Windows WebView2 和测试库检查新建、编辑、保存、重开、返回和关闭；测试不写用户原库、不使用真实模型额度。
