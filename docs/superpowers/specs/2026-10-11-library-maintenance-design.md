# 近期实测反馈：文件清理、记录移动、故事副本与筛选计数

日期：2026-10-11。状态：用户已确认并授权实施，代码与验证已完成。验证记录见 `docs/verification/2026-10-11-library-maintenance.md`。

## 已确认的需求

- 删除时可勾选是否删除源文件。用户已明确：源文件指 STE 库内保存的文件。
- 设置中检查孤立文件，展示占用并支持用户清理。
- 日记、总结可以从一个故事移动到另一个故事。
- 故事可以复制为独立副本，供修改前留档。
- 选择类型后，下方标签数量只统计该类型中的角色卡。
- 阅读体验作为后续方向，当前不确定具体改动。

## 现状与实现约束

当前文件库通过扫描磁盘重建索引，文件本身就是持久化数据。只从内存列表移除记录，重启后会重新出现。

`vault-backend.ts` 删除角色时删除档案和卡片，删除故事时删除故事数据、聊天和分支聊天；其他文件以及非空目录可能保留。角色页删除角色前将故事转为未绑定；统一删除服务需要覆盖角色库批量删除等入口，保持相同行为。

总结与日记共用 `SummaryItem`，通过 `bookId`、`branchId` 关联故事与分支。已有“复制为新记录”，尚无完整的故事复制服务。故事还可能包含本地聊天运行数据，复制时不能漏掉持久化记忆或复制正在进行的生成任务。

角色库当前用全量 `characters` 构建标签计数，实际列表则另外应用类型、搜索和标签过滤，导致显示口径不同。

当前工作区已有大量未提交改动。实施时基于这些现有改动增量修改，不重置工作区，也不将其他改动一并提交。

## 方案选择

推荐采用“保留区 + 手动检查 + 故事快照副本”：未勾选删除文件时，将相关文件移到库内专用保留区；检查结果由用户勾选清理；故事副本复制已保存的数据。

另一种做法是原地保留文件并维护排除清单，但所有索引、重新导入和目录移动都必须理解排除规则，维护成本更高。自动清理也能减少操作，但不适合当前尚需区分保留文件、有效独立资产和用户自放文件的情况。

## 1. 删除与库内文件

文件库中的用户主动删除弹窗增加“同时删除 STE 库内文件”，默认不勾选，并显示本次影响的文件数量与大小。

- 不勾选：移除应用中的条目，文件移入 `.ste/retained/<操作ID>/`，保留原始路径、记录类型、ID、时间和文件清单。索引扫描明确跳过该区域。通过移动保存文件，不额外复制一套占用空间。
- 勾选：删除当前条目的受管理文件，优先使用系统回收站；平台不支持回收站时，弹窗明确标明永久删除。不能吞掉失败后仍提示成功。
- 删除角色时，名下故事先转为未绑定；删除故事时，日记、总结和故事树保留为未绑定记录。弹窗说明关联内容的去向，避免把清理文件解释成删除所有下属记录。
- 条目所属的受管理图片、聊天记忆等文件纳入清单。共享世界书、预设、正则仍作为独立资产保留，不能因一个引用消失就删除。
- 未知文件不随目录递归删除。目录非空时保留，并可在设置检查中看到剩余内容。
- SillyTavern 原目录、导入来源及其他库均不属于操作范围。
- 浏览器 IndexedDB 模式没有磁盘原文件，此模式不显示文件删除复选框；记录移动与复制仍可用。

首轮统一角色、故事、日记/总结、自定义记录、故事树及独立资产的主动删除入口。立绘自身已有删除文件的逻辑，应接入相同选项和失败报告；自动历史淘汰不因这项改动自动转入保留区。

实施补充：角色附件的单独移除也提供默认不勾选的文件选项。附件沿用既有原地保留机制，避免改变外部程序使用的附件路径；保留后可在文件检查中定位查看，无法确认归属的附件不自动清理。删除整个角色时，仍受档案引用的附件随角色文件一起进入保留区或回收站。

删除服务先生成清单，执行前校验当前库、最新引用和文件状态。多文件操作保存可恢复的操作记录；失败时尽力还原，无法完整还原则报告已完成及待恢复项目，并保留恢复记录。正在生成或写入的条目不得同时删除。

## 2. 设置中的检查与清理

入口为“设置 → 数据与备份 → 文件检查与清理”，手动点击检查当前 STE 文件库。

结果区分以下内容，逐项显示路径、大小和判定原因：

| 类别 | 判定及操作 |
| --- | --- |
| 删除时保留的文件 | 有操作清单，可定位查看并勾选清理 |
| 确认失去引用的受管理文件 | 能证明由 STE 管理，且无任何有效引用；可勾选清理 |
| 无法确认归属的文件 | 用户自放文件、损坏数据或无法证明用途的文件；提供定位查看，不纳入一键清理 |
| 空目录 | 单独展示，确认后仅删除仍为空的目录 |

未绑定故事、独立资产、故事删除后保留的日记/总结，以及正式备份均为有效内容，不能仅因缺少上级引用就判为垃圾。保留区和未知文件应计入占用展示，让用户能解释空间去了哪里。

扫描跳过符号链接、库外路径，并识别未完成事务。读取或解析失败会使扫描结果标为不完整，此时不提供依赖完整引用分析的批量删除。清理前重新校验引用与文件版本；自扫描后被使用或发生变化的文件跳过并说明原因。切库后作废原扫描结果。

清理完成显示成功、跳过、失败数量及实际释放的库内空间；送入系统回收站时说明仍需清空系统回收站才能释放磁盘空间。

## 3. 跨故事移动日记与总结

在已有记录操作中增加“移动到其他故事”。目标选择器可按角色、故事名搜索，并允许选择目标故事主线或分支；默认主线。首轮支持单条移动，复用同一记录模型覆盖分卷总结、角色日记及自定义记录。

移动成功后，目标故事出现该记录，原故事不再显示。保留记录 ID、标题、正文、生成参数及原创建时间；更新归属、目标故事名和修改时间。跨故事移动转为手动保存，防止被自动历史清理淘汰。

原故事、原分支及生成楼层保存为来源快照。原楼层号不自动映射到新故事：未重新指定目标楼层范围前，不提供跳往目标故事同编号楼层的操作，也不直接用该范围重新生成。原来源可用于查看出处。再次移动仍保留最初生成来源。

存在未保存编辑时，复用现有保存保护；保存失败则停止移动。文件库须在目标持久化成功后再移除旧位置文件，失败保留可恢复状态；浏览器模式以记录更新完成移动。移动期间锁定记录并重新检查目标是否仍存在。

## 4. 复制故事为副本

角色故事列表和未绑定故事列表增加“复制故事”。默认名字为“原标题（副本）”，名称冲突时加序号，并保持原角色归属。

副本包含已保存的主线、全部分支、章节、收藏、阅读位置、故事设置、评分状态、日记、总结、自定义记录、故事树，以及继续本地聊天所需的持久化记忆。正在生成时不允许复制，提示等待生成完成并保存。

故事、分支和下属记录使用新的 ID；同步重映射关联、前情总结引用以及需要隔离的运行数据标识。副本中的自动历史记录转为手动保留。修改、移动或删除副本的内容不影响原故事。

副本清除 ST 写回目标和写回历史绑定，保留明确的来源说明，避免后续写回误覆盖原聊天。共享世界书、预设、正则继续以库内资产引用关联；用户界面称“库内副本”，完整离线备份仍使用现有导出备份功能。

复制从同一时点的持久化快照读取，文件库以暂存和提交方式写入，浏览器模式使用现有事务能力。全部成功才展示完成的副本；失败清理本次创建的数据并报告无法清理的残留。排除临时锁、进行中的请求、恢复事务和缓存。

## 5. 类型与标签计数

保留全库标签定义和显隐偏好，侧栏另算显示数量，避免切换类型时丢失自定义标签或已选条件。

- 标签计数集合 = 当前搜索结果中，符合当前类型的角色卡。
- 未选择类型时，统计所有类型；“未分类”仅统计尚未设置类型的卡。
- 标签统计按角色卡去重，同一卡重复标签或旧评价别名不重复计数；评分派生的评价标签与实际筛选逻辑一致。
- 已选标签继续按现有“同组或、跨组且”规则筛选列表；本轮标签数字不受其他已选标签影响，保持“该类型中有多少张此标签”的含义。
- 零计数遵循现有隐藏未使用标签偏好，但当前已选项必须可见并可取消。
- 类型按钮继续显示全库对应类型总数；标签管理中的使用数量继续按全库统计。

验收例：剧情类型有 18 张，其中 6 张符合“精品”，选中剧情后精品显示 6；其他类型中的精品不计入。取消类型恢复全库口径，输入搜索词则进一步收窄标签计数。

## 实施边界与验收

新增聚焦的数据服务分别承担删除计划与执行、文件检查、记录移动、故事复制；通过现有 Repo、VaultFs、写入队列和库隔离机制访问数据。界面复用现有弹窗、列表和通知样式。

关键验证：

1. 不勾选删除文件，重启后条目不复现，保留文件仍可查找；勾选后正确清理受管理文件。
2. 角色删除后故事仍能访问，故事删除后记录可作为未绑定内容访问；批量删除与单项一致。
3. 有效独立资产、共享图片、未绑定记录、外部路径、未知文件不被误删；扫描或引用读取失败不产生可直接清理的错误结果。
4. 注入多文件写入失败、磁盘失败和切库事件，确认原内容可恢复且不会跨库操作。
5. 日记/总结从 A 移到 B 后重启，归属正确、正文不变、不会错误跳楼层，保存失败时不丢记录。
6. 复制含主线、分支和下属记录的故事，重启后副本完整；修改或删除副本不影响原故事；副本无原故事的 ST 写回目标。
7. 18 张剧情卡案例、零计数、重复标签、评价别名、搜索、未分类、自定义标签及桌面/移动筛选栏回归。
8. 运行针对性 Vitest、TypeScript 检查和生产构建，并实际验证文件库与浏览器模式的关键交互；未运行的平台单独记录。

## 阅读体验后续记录

暂不改动。后续优先收集三类具体问题：长篇阅读时字号/行宽/行距是否疲劳；离开和返回是否能准确接着读；故事、日记与总结之间切换是否打断阅读。以具体场景决定改进方向。
