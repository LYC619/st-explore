## 原问题与用户纠正

用户截图中酒馆标签管理只有原有类型／评价，缺少“缺总结”。此前筛选只完成源码检查，11月10日稳定包明确未包含该修改，因此用户现用包不会出现新入口。

准备补包时，用户进一步纠正架构：仿Obsidian的本地归档工具应由库中的标签配置决定聊天显示，不能把四个整理标签固化为软件规则。旧固定名单方案停止交付，`src/lib/library-organizing-tags.ts`已移除，先前[整理标签浏览器记录](2026-11-10-organizing-tags.md)保留为历史，不能替代本版验收。

## 本版行为

- 在现有 `LibraryTagPreferences` 中增加 `chatVisible`，通过现有元信息持久化写入当前库的 `库信息.json`。无新增数据库或全局配置。
- 角色库标签管理每条增加“在聊天中显示”Switch。侧栏显隐与聊天显示分开。任意普通／自定义标签均可设置；类型、评价也可关闭。
- 旧库无字段时仅以原八项作为兼容初值；显式空数组保留为空。读取不自动写库，保存设置时落盘。
- 聊天列表和酒馆角色面板读取同一配置；按角色实际标签、类型与评分派生标签匹配。保留旧原生酒馆个人标签数据。
- 聊天列表入口改为“标签筛选”，增加“设置显示的标签”直达库管理；关闭管理回到聊天，移除已关闭的筛选条件。标签即使无匹配角色也可以保留显示。
- 标签的关闭／删除、分类删除、重新打开与多库隔离有回归；启用设置不修改角色卡与故事。详细原理见[库内标签与聊天筛选](../principles/library-tag-views.md)。
