## 已确认问题（尚未修复）

### R1 — P1：角色库原生单张/批量导出仍输出旧世界书

对应 A3。Library 的原生单张及批量入口分别在 `src/pages/Library.tsx:408`、`:362` 调用 `exportCharactersToDirectory`。该函数在 `src/lib/character-batch-export.ts:47` 直接使用传入角色构建文件，PNG 原样返回 `pngBase64`，JSON 直接序列化 `character.card`，没有使用 `buildCharacterExportSnapshot`。

复现：卡内旧书内容 A，当前绑定世界书已保存为 B；新快照函数得到 B，但同一角色经目录导出得到 A，且结果报告成功。用户从角色库正常导出时仍可能把旧资料带回 ST；多候选世界书的选择检查也被绕过。该模块本身没有在本批改动，这是 A3 修复遗漏的真实入口，不能以“旧文件未改”排除。

建议：所有角色卡导出入口共同读取当前角色/世界书快照；批量场景明确处理多候选与单项错误。回归应从原生 Library 路径覆盖 JSON 与 PNG，并提取导出卡内容核对 B，不能只测新 helper。

### R2 — P2：内容已保存、角色引用切换失败后，重试被误判为冲突

对应 A2。`saveAssetWithCow` 先保存资产，再更新角色引用；若后一步失败，调用者不会执行 `src/pages/WorldBook.tsx:296` 的保存基线更新。下一次保存会找到已经写入的派生副本，但 `:272–274` 把副本与旧基础内容比较，判作其他位置修改。

复现：两个角色共享 A；编辑新内容，首次角色引用更新注入一次临时失败。派生副本已保存，角色仍引用 A。点击“保存”后，引用写入尝试仍只有 1 次，页面变成冲突错误，角色引用始终没有修复。故障已经消失也不能在当前编辑会话直接重试完成。

建议：明确记录部分提交的目标、版本和阶段，让重试能安全完成引用切换；同时保留真正并发修改的冲突保护，不能仅删除版本检查。回归要分别覆盖写文件失败、引用失败、失败后继续编辑及外部确实改动。

### R3 — P2：冲突提示要求导出草稿，但导出也被同一冲突阻断

对应 A2 的失败恢复。世界书冲突消息建议“先导出草稿再重新打开”，但 `src/pages/WorldBook.tsx:486` 的导出前置操作强制 `await autosave.flush()`；失败即退出 `WorldBookExporter`，不执行文件保存。

复现：编辑器保留本地草稿 C，仓储另存 B；保存显示上述冲突提示，接着点击“导出世界书”，最终文件输出调用为 0，C 仍仅留在编辑器/恢复草稿机制中。这里并未证明草稿已经丢失，但产品提供的恢复指引无法执行。

建议：提供可明确识别的“导出当前未保存草稿”路径，不要求先覆盖库内新版本；正常导出仍可等待保存完成。回归断言输出含 C、仓储仍为 B。

### R4 — P2：高级模板生成无图片扩展名的接口 URL 后无法导入

对应 C0 的旧高级规则兼容。`buildPortraitLinks` 接受合法 HTTP(S) URL，下载器根据真实字节校验图片；但新增来源去重 `src/lib/portrait-import-identity.ts:6` 使用自动列表解析器的 `portraitUrl`，要求 URL 路径带图片扩展名。

复现：高级模板 `https://image.example/render?id=$1` 成功生成链接，网络夹具准备返回有效 PNG。实际后台任务在发出请求前就失败，`fetchCalls=0`，错误为“图片扩展名需为 PNG/JPEG/GIF/WebP/AVIF”。这同样影响使用无扩展名图片接口的旧规则。

建议：把来源 URL 规范化与自动模式的文件码/扩展名识别分开；高级 URL 保留协议和凭据等校验，图片格式交给实际响应字节。补齐预览、首次导入和去重路径回归。

### R5 — P2：高级模式源行改变后，旧手工 URL 被套到新图片

对应 C2 的稳定行身份。`src/lib/portrait-import-parser.ts:9` 把 `raw` 填成捕获出的名字，而不是原始匹配内容。`buildPortraitPreview` 用 `raw + occurrence` 生成身份，并按身份继承 `manualUrl`。

复现：源行 `Alice: abcd.png`，手动修正链接为 `manual.png`；之后把原文改成 `Alice: efgh.png`。解析器正确产生 `efgh.png`，但前后 raw 均为 `Alice`，预览继承旧修改，实际选中待导入链接仍为 `manual.png`。这会导入与新原文不一致的图片。

建议：高级解析保留实际匹配文本和原行位置，只有源内容身份未变时继承手工修正；同名、不同链接、同名换序和非连续原行均需要覆盖。不要只用显示名称识别源行。
