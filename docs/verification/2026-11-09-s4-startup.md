# S4：酒馆初始化等待的复现、修补与验证

日期：2026-11-09。执行：Codex 主 Agent。基线：`main / 73a6f461d4c2933cab5eb4b8a5a4c39323cda0af`，包含此前未提交的配置和五项反馈修复。

## 结果与范围

本次修复两条在独立 Windows 程序中复现的路径：

1. **非当前接口的缓存阻塞整个聊天。** 使用 Chat Completions 时，初始化仍同步等待 Text Completions 的采样器缓存；IndexedDB 升级被另一连接阻塞，会让正文为空、启动不完成。现在该缓存继续后台读取，不阻塞 Chat Completions；其他接口仍等待自己的采样器偏好。
2. **初始化未完成时无法关闭聊天。** 在内置模板等待期间点“关闭聊天”，原逻辑尝试保存尚未就绪的设置，不能释放当前页面。现在只有在尚未连接完整运行时、没有选中故事、无待保存正文且无输入／编辑／生成时，才仅排空宿主写入并退出；已有故事或改动仍走完整保存流程，失败仍保留页面。

启动提示拆分为内置模板、酒馆设置、头像、角色列表、背景、扩展清单、内置扩展、聊天显示扩展、启动回调、模型控件、助手等实际步骤。没有跳过必需扩展，也没有用超时后“假成功”放行仍在执行的脚本。

**结论边界：确认并修复一类能造成同样现象的阻塞，以及一个初始化退出缺陷；没有证据证明 11 月 7 日原始偶发记录恰好由该数据库锁触发，S4 不能整体按根治结案。** 独立测试无自然超时，故障用真实浏览器数据库锁／资源延迟注入复现。S5 关窗后进程不退出、真实总结拒绝、桌面配置恢复、Rust 跨进程锁未在本轮处理。

没有提交、推送、合并或正式打包。现有安装版不会自动获得本次改动。

随后在同一独立应用的合成页面中持有 `SillyTavern_TextCompletions` 数据库的旧连接，阻止 localforage 为缺少的对象仓库升级。通过普通聊天列表进入合成故事，实际停在 `applySettingsSnapshot`，20 秒后显示重载按钮，正文仍为空；关闭阻塞连接后立即继续加载。调用链：

`firstLoadInit → applySettingsSnapshot → loadTextGenSettings → loadApiSelectedSamplers → localforage.getItem → IndexedDB upgrade blocked`。

该缓存只控制文本补全采样器的手工选择；STE 宿主固定 `main_api: openai`，模型控件也禁用切换到其他接口。读取函数原有异常处理仍保留。缓存没有被清空、重置或迁移，延期完成不触碰故事正文。

第一轮原生复测已通过缓存阻塞与扩展重载，但在“模板等待 → 关闭聊天”失败。相应退出测试补充为先失败后修补；最终完整重跑通过。该失败保留，没有被后续成功覆盖。
