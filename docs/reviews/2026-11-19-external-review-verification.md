## 2. 数据风险：两项成立，多项队列指控不成立

### 同名新建确有并发覆盖

`vault-backend.ts:303` 的 `uniqueStem` 先列目录，`:612`、`:650` 再创建目录。两个不同 id 不共享上层按 id 的锁，底层没有将分配名字和占用名字作为一个不可分割操作。

本次用真实 `createVault`、`saveCharacter`、`saveArchiveStory` 和项目 `createMemFs`，通过 `Promise.all` 并发保存两条不同 id 的同名记录：角色或故事均只留下一个文件，重开库只剩一条。角色在当前会话中两个 id 可读回同一记录；故事有 id 校验，因此其中一条读回为空。这是数据层复现，尚不是 Windows 实际点击流程复现，也不能据此说每次批量导入都会发生；当前主导入循环存在顺序等待。

还补到报告未覆盖的关联竞态：在故事取得角色旧目录之后、创建子目录之前重命名角色，故事可以落到旧位置，当前会话可见而重开后消失。因此，仅按记录 id 排队、对同名分配加短锁仍不够；角色目录迁移与其故事/记录写入需要共同协调。若要下沉队列，必须核对父子锁顺序、同库多实例/多窗口边界及内部重入，不能宣称一把 JavaScript 锁就解决所有并发。

### PNG 与角色档案的提交确实会撕裂

`putCharacter` 在 `vault-backend.ts:622–635` 先更新索引和档案，再写入/删除 PNG。注入合成写入失败后确认三种结果：新建留下无图档案，更换留下新字段配旧图，删除失败后旧图被再次读回。

“先写图片再写 JSON”只能改变失败方向：若图片成功而 JSON 失败，会变成旧档案配新图。应处理图片、档案、索引与目录迁移的一致提交、失败回滚及崩溃恢复。现有 `vault-backend.test.ts:176` 的图片回滚用例测的是处理区 `cards` 仓储，不能替代正式角色 `characters` 的证明。

## 3. 权限问题成立，但不能用一个开关修好

### 系统打开与同源酒馆

`src-tauri/src/lib.rs:790–816` 的 `vault_open_path` 在授权路径检查后直接调用系统打开，无文件类型限制；附件入口也没有补齐。这意味着可执行文件或脚本附件可能被执行而非预览，值得优先收紧。具体扩展是否执行取决于系统文件关联；不能说报告列出的每种扩展都必然执行。白名单也并非“零破坏”，要保留目录定位与未知格式的明确反馈，并核对现有 HTML 使用方式。

`Roleplay.tsx:225、:334` 使用同源、无 sandbox 的酒馆 iframe，`host-bootstrap.js:14` 直接访问父窗口。若不可信脚本已能在酒馆顶层执行，就可以接触父窗口原生接口及同源存储，组合风险成立。本次未证明普通卡片自动触发攻击，也未做原生攻击链实测；当前第三方安装入口实际限制为两个固定版本、校验 SHA-256 的插件，内置用户脚本另有 `sandbox="allow-scripts"`，不能描述成任意扩展随意安装。

关闭 `withGlobalTauri` **不等于隔离**：锁定版本的 `node_modules/@tauri-apps/api/core.js:201–202` 仍通过 `window.__TAURI_INTERNALS__.invoke` 调用原生端；同源子页可访问父窗口这个对象。酒馆自己的 `window.__TAURI__` 又由 `host-bootstrap.js:76` 构造兼容桥。真正的隔离需要独立来源/沙箱、受限通信及原生权限共同设计。

当前 capability 虽没有授权前端插件 `open-path`，自定义 Rust 命令仍直接调用 opener 的 Rust API，因此不能指望该插件前端权限项替自定义命令拦截。依据为实际 capability 和本机锁定依赖源码，不是假定 Tauri 版本行为。

### 来源只读、历史授权及链接检查

`AuthorizedRoots` 没有区分用途和读写权限；`configured_root_values`、`restore_authorized_roots`（Rust `:600–687`）把 ST 来源与 STE 库放进同一集合，历史路径与当前配置合并。移除库注册没有相应撤销完整授权。报告这部分成立。

绝对路径检查（`:562–596`）只查叶子 symlink，未像相对路径一样逐级拒绝重解析点。不过 canonicalize 后仍执行 `ensure_contains`，所以不能把它说成已证明能任意越过授权根；普通 junction 指向未授权目录仍应被拒绝。

修复还需要覆盖报告漏掉的两点：

1. `config_set` 可写入根目录配置，下次启动又把配置转换成授权；授权来源本身也需要约束，不能只拆两个集合。
2. `vault_write_abs_text` 也用于 Markdown 等文本导出（`src/lib/text-file-export.ts:53`），绝对二进制写入用于阅读包导出（`src/lib/reading-pack/save.ts:38`）。不能把通用命令直接全部限成 `.jsonl`；应区分 ST 显式写回、库写入、临时导入与用户选择目标的导出。后缀允许本身不代表用户批准覆盖。

## 5. 建议顺序与后续验收

建议先解决实际失败的两项 CI 路径断言、正式角色图片/档案一致性，以及同名分配和父子目录迁移竞态；系统打开限制、宿主 JS 规则可分别作为小批次。原生来源只读、授权撤销和酒馆隔离应各自明确边界后实施，避免用无效开关制造“已安全”的结论。性能优化按合成测量和用户实际慢操作选择；字体、玩法、发布和分支清理保持独立决定。
