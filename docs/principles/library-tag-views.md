# 库内标签与聊天筛选

2026-11-10，用户明确：STE 是类似 Obsidian 的本地归档工具，哪些标签在聊天里出现应由当前库决定。不要为“缺总结”等某次整理使用的标签编写产品白名单。

## 数据归属

角色的标签值仍保存在角色档案的 `tags` 中。标签定义、顺序及视图显示设置沿用当前库根目录的 `库信息.json` → `libraryTags`。新增的 `chatVisible` 数组保存开启“在聊天中显示”的标签完整名称；它等价于各标签的聊天显示开关，不包含故事正文。

角色库侧栏的 `hidden` 与聊天的 `chatVisible` 独立。隐藏侧栏标签不删除角色上的标签，也不关闭其聊天显示。软件不根据某个标签的名字判断业务含义，不推断“总结是否完成”。

聊天列表与酒馆角色面板读取同一份 `chatVisible`，统一使用角色标签、类型与评分派生值进行匹配。标签关闭或删除后，不再作为聊天筛选项；已经选中的失效筛选在重新读取库配置后清除。被开启的标签即使当前没有匹配角色仍可显示，筛选结果为零。

## 旧库兼容

旧库没有 `chatVisible` 字段时，以原先八种类型／评价作为初始选择。用户可以逐个关闭；显式 `[]` 表示全部关闭，不能在下次启动时重置成默认值。读取不会为了迁移自动写库；下一次保存标签设置时将完整选择写入库文件。默认值只是旧行为的兼容起点，聊天运行时没有固定类型或整理状态白名单。

`缺总结`、`总结完`、`缺日记`、`日记完` 都是普通标签。用户可给任意现有或自定义标签开启聊天显示。完整库搬迁时设置随 `库信息.json` 一起带走；单独导出一张标准角色卡不携带整个库的视图配置。

## 操作入口

- 角色库 → 标签管理 → 选中所属分组 → 标签下方“在聊天中显示”。修改即时保存到当前库。
- 聊天 → “设置显示的标签”可直接打开同一个管理界面，关闭后返回聊天列表。
- 聊天列表使用“标签筛选”；酒馆角色面板使用原生标签按钮。后者的个人酒馆标签记录继续保留，与库内显示设置分别保存。

此设置决定哪些筛选项可见，不代替给角色打标签。筛选按角色显示其全部故事，不声称逐故事、逐卷的完整性。
