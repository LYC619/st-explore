# 文件库整理流程：隐私边界复核与纠正

日期：2026-11-08；执行：Codex。范围：复核既有执行链路、修订操作文档和后续设计，不恢复生成、不改产品运行代码。

## 用户已明确的边界

> 只允许酒馆发给我配置的模型；禁止正文进入 Codex 或其他服务。

这项决定覆盖旧流程、旧任务授权与旧检查方法。原聊天、角色私密设定、世界书内容、模型返回、总结和日记都在保护范围内；摘录、语义转述、截图及包含内容的日志同样不能返回 Agent。不能通过另一个 Agent、云端审查器或“只提取不阅读”的说法绕开边界。

本机程序为计数、分段、提取标签和登记而读取文件，与把内容放入工具输出交给 Codex，是两件不同的事。前者限于既定整理用途，后者被禁止。酒馆向用户配置模型发送上下文是获准的数据流，因此这套流程不能描述为“全部离线”。

## 已确认的问题

既有执行记录及本次静态脚本复核支持以下结论。本次没有为重现这些问题重新打开原聊天、生成结果或截图。

| 环节 | 原来的问题 | 更正 |
| --- | --- | --- |
| 内容筛查 | `screen-metadata.mjs`读取卡片／聊天并输出匹配词；`age-context.mjs`输出年龄附近原文；`inspect-metadata.mjs`输出从设定推导的内容线索 | 这些不是无内容的技术状态。停止按此方法筛查，不再把私密文本或推断传给 Codex |
| 批量分类 | `classify-queue.mjs`按角色名映射类别，再应用到该角色的待处理任务 | 历史标签不是酒馆给出的状态，也不是逐段确认的事实；不能据此宣称每一段都已核实或已完成 |
| 浏览器操作 | 原聊天页面截图含正文，已经作为工具结果返回 | 页面位于 localhost 不会让返回给 Codex 的截图留在本机；后续不能使用会自动返回页面内容的控制入口 |
| 诊断输出 | 曾完整打印含嵌套私密字段的原生会话头 | 文件头、metadata、日志和异常也可能含正文；不能因字段名称就视为可公开 |
| 提取与登记 | 本地脚本可完成原文提取，但生成标题、文件路径、原始异常及校验差异也可能带出内容 | 结果与失败只能通过固定字段状态接口上报，内容及映射留在本机 |

因此必须承认：**历史上已有私密片段和截图进入 Codex 的模型上下文，不能说“从未上传”或“全程只在本地处理”。** 这次改文档不能撤回已经返回的内容，也不代表删除了服务端历史。

没有完整的历史出站记录，无法从当前脚本确定全部接收方、传输数量或服务端保留情况；也未核实账户的数据保留／训练设置。旧日志中出现外部脚本地址本身不足以证明该脚本传走了正文，反过来也不能据此保证没有其他传输。

## 纠正后的最短流程

1. **本机盘点**：本地程序按消息数筛选活动故事，按原楼号每50楼分段；映射、哈希、源资料及工作副本留本机。
2. **酒馆生成**：原生 SillyTavern 使用用户当前配置的模型、预设和扩展，仅接收固定任务指令“生成总结”／“生成日记”。
3. **本机提取**：程序从已保存的最终回复提取；日记只取 `<diary ...>...</diary>` 内文。格式不确定返回固定状态，由用户在本机查看，不返回片段让 Codex判断。
4. **本机登记**：复用 STE 的记录格式，校验故事／分支／楼段、非覆盖写入和回读一致性。
5. **只报状态**：Codex 接收不透明任务编号、类型、楼段、计数、字节数、固定状态码和校验布尔值。正文及质量审查留给用户。

用户看到的本地界面可以正常显示角色名和内容；Agent 的接口是另一个经过缩减的出口。不能把本地玩家界面截屏后再声称“Agent只看状态”。

## 本机数据与 Agent 输出的分界

| 数据 | 本机程序／玩家界面 | Agent 工具结果、报告及外部服务 |
| --- | --- | --- |
| 聊天、角色设定、模板、原始回复、总结／日记 | 按任务需要读取、保存；玩家自行查看 | 禁止正文、摘录、转述、截图或编码后输出 |
| 真实名称、标题、路径、稳定ID、源文件哈希 | 保存定位和恢复所需映射 | 默认替换为本次随机别名；不携带模型生成标题 |
| 任务类型、楼段、数量、耗时、字节数、是否相等 | 可以计算 | 仅经允许字段与类型检查后返回 |
| 错误／拒绝／格式问题 | 本地保留必要诊断；用户按需查看 | 固定错误码和尝试次数；禁止 `error.message`、堆栈、请求／响应体、断言差异直接透传 |
| 网络与扩展配置 | 酒馆使用用户指定的服务与所需环境 | 不新增直调模型、云端评审或上传；扩展的出站行为仍需另行验证 |

返回示例仅为接口要求，尚非已实现能力：

```json
{"task":"t-0042","kind":"diary","range":[50,99],"state":"registered","bytes":2048,"readbackEqual":true}
```

本地检查可以判断标签是否闭合、响应是否为空、来源与范围是否一致，不能将这些结构检查包装成内容质量或年龄判断。无法在允许边界内判定的任务停在固定待用户处理状态，不擅自扩大读取，也不把隐私限制用作继续已知不允许任务的理由。

## 旧工具与证据怎样处理

`.cache/library-summary-batch/` 内仍留有原聊天快照、原始回复、准备入库记录、账本和旧脚本。`.gitignore` 忽略缓存只避免通常的 Git 跟踪，不是加密、传输隔离或删除保证。未重新打开这些私密数据，未把它们加入公开报告附件，也未自动删除证据或现有成果。

旧脚本和旧浏览器操作方式**暂停复用**。同目录增加 `PRIVACY-HOLD.md` 作为后续接手提醒；这是文档标记，不是程序开关或技术隔离。不得通过运行旧筛查脚本、输出完整JSON、抓DOM／可访问性树、截图、浏览器控制台、HAR或全量错误来继续排查。

恢复自动化前，应有经过合成数据验证的本地控制器：固定状态接口、原生ST触发及保存凭据、标签提取和非覆盖登记。测试应在聊天、设定、标题、异常及生成结果中放入合成标记，确认工具输出及日志不包含这些标记；失败时也只报固定错误码。网络边界必须验证，不能只搜索源码字符串。原始素材不得作为测试回显或快照附件。

本次仅修订流程和后续设计，**尚未实现或验证上述隔离控制器**，因此没有恢复剩余故事的自动生成。
